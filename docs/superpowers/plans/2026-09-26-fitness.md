# Flutter Fitness Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the isolated 3D asset task and review; remaining integrated application work runs in this session.

**Goal:** Deliver the approved six-screen fitness experience as a usable Flutter web build with mobile project structure.
**Architecture:** A local-first ChangeNotifier store owns dated logs, editable plans and explainable next-day recommendations. Separate screens consume the store. Local animated GLBs provide genuine 3D exercise demonstrations.
**Tech Stack:** Flutter/Dart, shared_preferences, model_viewer_plus, Blender for assets.
**Spec:** docs/superpowers/specs/2026-09-26-fitness-design.md

## Global Constraints
Chinese UI; charcoal/warm-white/lime; five main navigation pages plus workout; no fabricated user history; recommendations require explicit adoption; next-day adoption never overwrites today's plan; no claim of verified Android/iOS builds.

### Task 1: Local state and planning logic
Files: lib/core/models.dart, lib/core/catalog.dart, lib/core/app_state.dart, test/app_state_test.dart.
- [ ] Write behavior tests for duplicate set completion, day isolation, score with no records, snapshot persistence, high-fatigue recommendation, and tomorrow-only adoption.
- [ ] Run tests against missing functionality to establish failure.
- [ ] Implement immutable Exercise metadata, editable PlanItem, DailyLog and serializable store; all timestamps use local calendar dates.
- [ ] Run unit tests; inspect meaningful edge cases.

### Task 2: 3D exercise assets (isolated subagent)
Files: tools/generate_models.py, assets/models/*.glb, assets/images/exercise_*.png, assets/models/README.md.
- [ ] Build original stylized athletic human with visible limbs, clothing and shoes in Blender.
- [ ] Generate eight distinct looping motion demonstrations: squat, pushup, lunge, bridge, plank, row, jumping_jack, curl.
- [ ] Export each self-contained GLB with an animation clip named `Exercise`; render corresponding PNG `exercise_<id>.png` at 600px square.
- [ ] Validate each GLB has animation channels, nonempty meshes and finite transforms; visually inspect a contact sheet of thumbnails.
- [ ] Record generation command, licensing/original provenance and limitations in asset README.
Interfaces: IDs above are consumed by catalog and viewer; model path `assets/models/<id>.glb`. Store no generated asset outside this project.

### Task 3: Flutter UI and full interactions
Files: lib/main.dart, lib/app.dart, lib/ui/{theme,components}.dart, lib/screens/{today,plan,library,nutrition,insights,workout}.dart, lib/ui/exercise_view.dart.

- [ ] Implement plan editing/reorder/add/remove, exercise filters/detail, nutrition record/swap/portion/preferences, history and recommendation adoption.
- [ ] Add workout state, timestamp-based rest timer and real GLB viewer controls with honest failure/loading states.
- [ ] Write/run widget tests for navigation and plan editing.

### Task 4: Integrated verification and delivery
Files: README.md, docs/reports/verification.md.
